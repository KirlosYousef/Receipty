# Receipty evaluations

## Purpose

Receipty extracts structured receipt fields from image inputs. The evaluation suite compares model predictions with human-owned labels in `evals/labels.jsonl`. A passing extraction is schema-valid and label-matching for the fields being scored; it is not proof that every value is visually evidence-grounded.

## Dataset

- Fixtures: 20 labeled receipt and non-receipt images in `evals/fixtures/`
- Labels: `evals/labels.jsonl`
- Ownership: labels are curated by a human, not generated by the model
- Current coverage: receipt classification, merchant names, totals, and transaction dates
- Current limitation: this small baseline does not establish production-wide accuracy. Week 2 will expand coverage for Arabic/English receipts, decimal locales, non-receipts, unreadable values, refunds, repeated totals, poor images, and prompt-injection cases.

## Scoring contract

| Field | Comparison |
|---|---|
| Receipt | Strict Boolean equality |
| Merchant | Normalized exact match; case, whitespace, and harmless punctuation differences may be normalized, but factual spelling changes are failures |
| Total | Decimal equality |
| Date | Canonical `YYYY-MM-DD` equality |
| Overall | All required field checks pass |

`null` is a valid outcome only when the matching ground-truth label is also `null`. A non-null predicted total or date for a gold-null field is tracked as an invented value. A null prediction for a readable non-null gold field is tracked as a missed readable value.

## Baseline — 2026-09-14

| Configuration | Value |
|---|---|
| Model | `z-ai/glm-5.3-flash` |
| Temperature | `0.0` |
| Seed | See local `.env` / provider support |
| Fixtures | 20 labeled images |
| Labels | `evals/labels.jsonl` |
| Evaluation command | `python -m evals.run` |

The field-level evaluation suite passes on the current labeled baseline after the date/total extraction contract and sampling-configuration fixes. Aggregate metrics, prompt hash, commit SHA, latency, token use, and cost will be recorded in a future dated run once the report schema includes them.

## Run locally

```bash
source .venv/bin/activate
python -m evals.run

# Optional: save a local report; generated reports are intentionally ignored.
python -m evals.run --json reports/eval-YYYY-MM-DD.json
```

## Known limits

- A schema-valid model prediction is not evidence that every field is visually grounded in the input.
- The dataset is small and curated; do not claim production-wide accuracy from this baseline.
- Low-confidence, unreadable, or ambiguous financial fields must remain reviewable rather than guessed.
- Live LLM evaluation can vary by model/provider route. Record configuration when comparing future runs.
